# RC3 Facilitator Recovery Playbook

Use only on the authorised isolated certification event. First capture the participant/submission ID, timestamp, screenshot and request ID. Never create a replacement participant, reallocate a team, transfer leadership or adjust credits merely to hide a failure.

| Incident | Facilitator action | Verify before resuming | Escalate/stop when |
|---|---|---|---|
| Participant disappears | Ask participant to reopen the original link once. In **Control Centre → Team Management**, select the exact ParticipantID and choose **Recover Participant**. Return the recovery payload to the participant. | Same ParticipantID, TeamID, country, flag, leader state and credits; row count unchanged. | Participant cannot be found, recovery changes durable fields or creates a row. |
| Participant refreshes | Wait for automatic restoration. If the join screen appears, use **Check Existing Registration** and select only the verified existing identity. If needed, use **Recover Participant**. | Original identity and runtime position return; no allocation runs. | Identity is ambiguous, team changes or a second row appears. |
| Leader disappears | Reopen the original leader session. If not restored, select the original leader in **Team Management** and choose **Recover Participant**. Do not choose **Transfer Team Leader** for recovery. | Original leader retains TeamID and leader-only submission rights; exactly one team leader. | Original leader is missing, rights differ or more/less than one leader exists. |
| Upload fails | Preserve the participant session and evidence file. Check network, then retry once from the same submission screen. Do not approve until one SubmissionID is visible. | One upload and one pending canonical submission; no award yet. | Two submissions appear, file is unavailable after retry or participant identity changes. |
| Broadcast fails | Confirm the correct EventID and projector connection. Reapply the current payload once with **Apply Broadcast**. If still absent, **Pause Event**, tick **Confirm non-destructive runtime restart**, choose **Restart Runtime**, then **Resume Event** and reapply once. | Correct projector receives one event-scoped broadcast; participant state is unchanged. | Another event is affected, restart changes participants/runtime position or broadcast remains absent. |
| Participant duplicates | Stop that participant and record both ParticipantIDs. Do not merge, delete, move or award. Close registration if duplicates continue and escalate for record-exact review. | No further duplicate is created; original records and audit evidence remain intact. | Duplicate creation continues or identity/team ownership cannot be proven. |
| Submission duplicates | Do not approve either row. Record both SubmissionIDs and idempotency/request evidence. Pause approvals for that activity and escalate for canonical reconciliation. | No credits or leaderboard delta; duplicate records remain untouched for audit. | Either row is already awarded, balances differ or more duplicates appear. |

After any recovery, repeat only the failed certification from its start. A recovered operational interruption may pass; a durable-data mutation, duplicate or unreconciled award remains an RC3 failure.
